# 内容コーディング規約 v1（pilotで検証する案）

## 単位と基本規則

1投稿1行。本文、添付画像中の文章、投稿時点の媒体情報を対象とする。リンク先の後日更新内容や返信欄は主分類に使わない。動画は視聴できたかを記録し、内容分類が未確認ならunknown。分類の根拠箇所はローカルにのみ保存する。

二値は1=あり、0=確認してなし、null=判断不能。画像等が欠け、未観測部分に該当情報があり得る場合は0にしない。観測できた本文で既に1なら1とできる。社名「イオン北海道」やプロフィール由来の地域情報は全投稿の地域性の根拠にしない。

以下の例はすべて架空であり、実際の投稿引用ではない。

## 地域性：排他的でない次元

| フィールド | 1の条件 | 例と境界 |
|---|---|---|
| local_name_only | 地名はあるが下記の具体的結びつきがない | 「北海道のみなさん、おはよう」だけ。社名・定型タグのみは含めない |
| local_origin | 商品・原料の北海道産地を明示 | 「十勝産の小麦使用」。単なる「北海道フェア」は産地不明なら0 |
| local_store | 特定の道内店舗/場所での具体的行動・サービス・催事 | 「札幌○○店で今週末、相談会」。店舗名の署名だけは0 |
| local_people_culture | 地域の生産者・団体・文化・歴史との具体的関係 | 生産者紹介、地元団体との活動、地域祭りの説明 |
| local_boilerplate | 社名・定型タグ・定型署名だけに地域語がある | 「新商品発売 #北海道 #イオン北海道」 |
| local_substantive | origin/store/people_cultureのいずれかが1 | 主説明変数。未確定次元があり全て0と確認できなければnull |

local_name_onlyは実質的地域性と同じ情報箇所には付けない。local_boilerplateは他の次元と併存可能。本文/画像/動画のどこを根拠にしたかsource_modalityを別記録する。地域語の単純件数を強度スコアと解釈しない。

local_substantive=1でも読者が道民、地域愛着が高い、地域貢献に成功した、とは判断しない。各地域次元と合成二値は同じ回帰式へ同時投入しない。

## 懸賞・報酬と反応要求

| フィールド | 定義 |
|---|---|
| prize_draw | 抽選による景品・金銭・商品提供 |
| reward_for_action | 特定のSNS反応・行動を条件にした確実/抽選の便益 |
| require_like / require_repost / require_reply / require_follow | 応募条件として明示された各行動。複数可 |
| commercial_promotion | 価格、値引き、販売促進。懸賞とは独立 |
| cta_nonreward | 報酬と結びつかない来店・閲覧・反応の呼びかけ |
| question_nonreward | 報酬と結びつかない回答可能な問い。単なる疑問符は除く |
| campaign_id | 共通の企画・応募期限・公式説明から付与した企画群。通常投稿の欠損を一つの巨大群にしない |

主分析の非懸賞とはprize_draw=0かつreward_for_action=0を確認できる投稿。名称に「キャンペーン」があるだけでは除外しない。「牛乳10%引き」はcommercial_promotion=1でも非懸賞。「フォロー＆リポストで抽選」はprize_draw=1、reward_for_action=1、require_follow/repost=1。

条件がリンク先にしかなく内容確認できない場合はunknown。リンク先の条件を分類に利用する拡張を行うなら、取得時点と保存方式を事前に固定し、主分類と混ぜない。景品価値・当選人数・広告規模は不明が多ければ無理に推定しない。

## その他の内容と機械特徴

informative（具体的情報）、entertaining（冗談・遊び等）、commercial_promotionは複数ラベル可。humanized_toneは一人称・担当者の日常・対話口調という観測可能な表現を別記録し、企業人格の心理尺度としない。

商品大分類は食品/非食品/複数/該当なし/不明から開始し、pilotで細分化の可否を決める。商品カテゴリと地域性を混同しない。災害告知・季節行事・CSRは探索用フラグ。

媒体はnone/image/video/GIF/mixed/unknown。ネイティブ動画と外部動画URLは別フィールド。文字数は元の本文のUnicodeコードポイント数（URLを含む）として実装版を固定。絵文字数は結合絵文字をどう数えるかを仕様化するまで主統制にしない。時刻特徴はJST、保存時刻はUTC。

## 信頼性と自動分類

- pilotから練習用約30〜50件で判断規則を改訂。その後、別の無作為標本約100件以上を二名が独立評価する。件数は実行可能性の目安。
- 評価者にはいいね等の反応数とモデル結果を見せない。合議前の値を凍結して一致率、κ、混同行列、陽性率をフィールド別に報告。
- 稀な陽性に対しては追加の重点標本も使えるが、無作為標本と混ぜて代表一致度を出さない。定数ラベルのκは未定義とする。
- この計画ではκが0.70未満なら規則を再検討する運用目安とする。普遍的な合格基準ではない。低頻度では一致率・陽性一致と併せて判断し、主地域性が再現できなければH1を延期。
- 可能なら本分析も二重分類し、不一致は第三者または根拠付き合議で確定。規約の版、評価者、日付、元ラベル、合議ラベルを別保存。
- 自動分類は人手分類と独立したholdoutでmacro-F1・ラベル別precision/recall・誤り例を評価する。LLM利用ならモデル版、prompt、温度、日付を固定。機密データの外部送信を前提にしない。
- 自動分類が十分でなければ人手に戻す。100件の高い精度だけで稀な地域ラベルの測定誤差が解決したとはしない。
